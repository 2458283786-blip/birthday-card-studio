# 数字收藏卡 V2 主规范(唯一有效产品规范)

> **本文件是 V2 的唯一产品规范。** 与它冲突的旧文档(已归档到 `archive/v1-birthday/`)一律不作数。
> 依据:《数字收藏卡 V2 最终整改方案》(2026-09-16 核验)+ 现行仓库实际代码。
> 最近更新:见 `docs/V2-进度日志.md`。

---

## 0. 一句话
**把照片做成一件属于客户的数字收藏品** —— 工作台是**制卡人员的生产工具**,不是让客户自己设计卡的地方。

## 1. 产品定义
| 项 | 定义 |
|---|---|
| 产品名 | 数字收藏卡生产工作台(Digital Collectible Card Studio) |
| 使用者 | **制卡人员(你)**;客户**不进入工作台** |
| 客户输入 | 照片 + 文案 + 必要的纪念信息 |
| 核心过程 | 客户内容 → **AI 分析** → **AI 设计提案(3~4 个)** → 制卡人员选择 → **程序化生成** → 人工精修 → **QA** → 导出 |
| 输出 | `front.png` / `back.png` / `card.json` / `preview` / `showcase` / 实际存在的分层与材质资源 / **Card Package** |
| 客户侧 | **Standalone Card Showcase**(手机优先);微信小程序 = 交付后的**收藏端** |
| 核心原则 | 工作台负责"把订单做成卡";AI 负责**设计判断**;程序负责**确定性执行** |

## 2. 四个正交维度(不要混为一谈)
| 维度 | 取值 | 回答的问题 |
|---|---|---|
| **Content Occasion** | Birthday / Anniversary / Travel / Graduation / Pet / Personal … | 这张卡**纪念什么** |
| **Design Language** | **PORTRAIT / CYBER / EDITORIAL / MEMORY** | 这张卡**长什么样** |
| **Material** | Matte / Pearl / Foil / Gloss / Holo | 卡面**什么质感** |
| **Interaction** | Parallax / Flip / Touch Drag / Device Motion | 卡**怎么动** |

> Birthday **不再等于**一个模板;Holo **不再等于**一种风格。

## 3. 四套 Design Language(每套先做 **1 个标杆款**)
| 语言 | 输入照片 | 视觉方向 |
|---|---|---|
| **PORTRAIT** | 纯色/干净背景的**单人照** | 人物分层、艺术背景、姓名、大标题、Edition/编号、局部 Foil/Holo |
| **CYBER** | 夜景、黑底、年轻、科技、酷感 | 黑底、HUD、霓虹、编号、线框、金属/玻璃材质 |
| **EDITORIAL** | 生活照/旅行/生日/毕业/情侣,**不要求抠图** | 大照片、大字体、非对称、留白、摄影杂志感 |
| **MEMORY** | 有故事感、纪念感 | 胶片、纸张、拼贴、日期、手写感、克制纹理 |

**第一阶段不做几十个模板**:先证明四个方向各自能做出一张真正惊艳、可交付的卡,再扩数量。

## 4. 工作台 V2 工作流(界面依此重构)
```
① 客户内容   照片 / 姓名 / 纪念日期 / 客户文案 / 备注
② AI DESIGN  Photo Analyzer → PhotoDNA → 推荐 Design Language
③ PROPOSALS  [方案 A] [方案 B] [方案 C] [重新生成]     ← 实际卡面提案, 不是模板缩略图
④ EDIT       [正面] [背面] [3D]   构图 / 文字 / 材质 / 景深 / 高级(默认隐藏)
⑤ QA         ✓Artwork ✓文案 ✓Card ID ✓Date ✓Back ✓QR ✓Showcase ✓Package
⑥ EXPORT     导出 Card Package
```
顶部导航:**新建订单 / 历史订单 / 卡片库**。

## 5. 字段(只填真正的订单信息)
| 字段 | 状态 | 来源 | 展示规则 |
|---|---|---|---|
| 姓名 `name` | 保留 | 客户/制卡人员 | 按设计需要 |
| 纪念日期 `date` | 保留 | 客户/制卡人员 | **背面必选**;正面按设计 |
| 客户文案 `message` | 保留 | 客户 | 按设计进入 Artwork |
| 备注 `note` | 保留 | 制卡人员 | 仅工作台内部 |
| **Card ID** | **系统自动生成** | 系统 | 背面必选;**禁止手工设计** |
| `createdAt` | 自动 | 系统 | 内部记录,第一阶段不展示 |
| `creator` / `owner` | 可选 | 系统/制卡人员 | **有数据才显示** |
| QR | 可选 | 系统/制卡人员 | 有数据才显示 |
| `video` | 预留 | 系统 | 第一阶段不做完整视频系统 |
| `collection` | 预留/兼容 | 系统 | 由 Card Package 支持 |

内部唯一 ID 与展示 ID **分离**。

## 6. 正面 / 背面规则
**正面 = 一张完整 Artwork**
- 不强制标题、`YOUR DAY`、年龄、姓名或任何固定信息;内容服从 Design Language 与构图
- **不为填字段破坏人物、留白或视觉中心**

**背面 = 统一 Card Identity**
- **必选**:Card ID + Date
- 可选:Created by / Owned by / QR —— **为空时完全隐藏**
- 第一阶段**不做** `#027/100`、稀有度、发行量、价格

## 7. AI 架构(职责边界)
```
客户照片+内容 → Photo Analyzer → PhotoDNA → AI Art Director → 3~4 提案
             → Procedural Renderer → AI Visual Critic → 必要时自动修正 → Card Package
```
**AI 负责**:照片理解与分类 · 色彩/构图/主体/负空间判断 · **推荐 Design Language** · 布局/字体层级/颜色/材质建议 · 生成或选择背景 Artwork、纹理、Photo Echo · **生成多个候选** · Visual Critic 检查文字冲突/主体遮挡/留白/层次/风格一致性。

**程序负责**:Card ID、Date、JSON、文件命名 · 确定性文字排版与 QR · 图层、尺寸、导出 · Material/Holo/Parallax/Flip/Touch Drag · Showcase 与 fallback · Card Package。

**AI 不直接生成"带文字的最终卡"。**
PhotoDNA 最低字段:`palette / brightness / contrast / warmth / saturation / subject{detected,bbox,mask} / composition{subjectPosition,negativeSpace,horizon} / scene{type,mood}`。

## 8. 照片处理
- 默认**保留整图,不强制抠图**;只有**可靠 mask** 才做主体分层/overflow
- 纯色背景单人照 → 走 **PORTRAIT** 专门路线;复杂背景**不得被低质量抠图破坏**
- **始终保留 source 原图**
- **Photo Echo**:提取主色/辅助色/边缘色/纹理/光影结构,用于背景、细线、文字颜色、局部材质
- 文字**避开脸部与主体**,不为固定坐标牺牲构图

## 9. Material / Holo / Interaction
| 能力 | 定位 | 原则 |
|---|---|---|
| Matte | 基础材质 | 适合 Editorial / Memory |
| Pearl | 材质选项 | **不默认铺满** |
| Foil | 局部质感 | 优先用于文字/边缘/小面积图形 |
| Holo | 增强材质 | **静止低存在感,倾斜才出现** |
| Parallax | 展示层 | 强化空间,**不抢 Artwork** |
| Flip | 展示层 | 背面信息来自 `card.json` |
| Device Motion | 增强交互 | 不可用时回退 Touch Drag |

> **Holographic is a material, not the artwork.**

## 10. Card Package(三端稳定契约)
```
CARD-0027/
  card.json
  front.png  back.png
  preview/front.jpg  preview/back.jpg
  layers/       # 按实际存在的资源
  materials/    # 按实际存在的资源
  showcase/showcase.html
  video/front.mp4   # 仅预留, 不要求存在
```
**fallback 规则**:缺分层→用 front.png;缺 Holo→普通材质;缺 3D→2D;无 Device Motion→Touch Drag。**所有 optional 资源必须自然隐藏。**

Schema **v2 目标结构**(不要求一次覆盖,必须**兼容迁移**,旧包仍能打开):
`schemaVersion / cardId / displayId / occasion / designLanguage / template / title / date / createdAt / creator / owner / content{name,message,signature,note} / front / back / layers / material{type,holoEnabled} / interaction / media / qr / status / cardVersion / metadata / collection`

## 11. 小程序与 Showcase
- **Standalone Showcase** = 客户最终看到的成品入口(手机优先)
- **微信小程序** = 交付后的收藏端,**不反向绑架工作台**;读 `card.json`,**不把设计硬编码进小程序**
- 本轮**不扩展**社交 / 支付 / 交易市场

## 12. 硬性约束(违反即打回)
1. 先检查现有代码/入口/数据结构/资源路径/测试,**禁止未经检查直接重写**
2. 禁止把旧 Birthday 文档当作 V2 规范
3. 禁止继续把"增加 Birthday 五套模板"当第一优先级
4. **禁止把 AI 设计继续做成单纯选色/调参数**
5. 禁止把 Holo/3D 当作 Artwork 本身
6. 禁止强制所有照片抠图
7. 禁止强制所有卡出现固定正面字段
8. 禁止手工填写 Card ID
9. 禁止为视频/Collection 预留引入复杂后端
10. **禁止删除现有 miniprogram**(先检查依赖)
11. **禁止破坏旧 Card Package / Showcase**(必须兼容路径)
12. 每个阶段都要报告:**修改文件 / 原因 / 运行方式 / 测试结果 / 已知问题**

## 13. 分阶段计划
| 阶段 | 任务 | 完成标志 |
|---|---|---|
| **Phase 0** | 冻结/备份当前可运行版本 | 建立安全基线 |
| **Phase 1** | README / AI Prompt / 工坊说明统一;Birthday 文档归档 | 只有一个 V2 主规范 |
| **Phase 2** | 工作台 UI 重构 | 订单→分析→提案→精修→QA→导出跑通 |
| **Phase 3** | 4 个 Design Language 各 1 个标杆款 | 视觉质量先过关 |
| **Phase 4** | Photo Analyzer + PhotoDNA + Art Director + 3~4 提案 | AI 真正进入设计环节 |
| **Phase 5** | Visual Critic + 自动修正 | 减少人工试错 |
| **Phase 6** | Schema / Package / Showcase 收敛 | 生产与交付闭环稳定 |
| **Phase 7** | 验证现有小程序兼容性 | 新卡可进入现有收藏链路 |

## 14. QA 验收标准
**A 产品流程**:一个工作流跑通全链;客户无需进入工作台;首页不再以 Birthday 五套为核心;**AI 按钮真正承担设计职责**;高级参数默认隐藏。
**B 视觉**:卡面首先成立为 Artwork;关掉 Holo 静态卡也成立;普通照片不因强制抠图损失背景;**四套语言一眼可区分但同属一个品牌系统**。
**C 数据**:Card ID 自动且唯一;`date` 与 `createdAt` 分离;`creator` 与 `owner` 分离;optional 空值不渲染空白;旧 Card Package 仍能打开。
**D 交付**:front/back/card.json/preview/showcase 完整;Showcase **无** debug/滑块/AI 按钮/文件名/工具栏;材质与 3D 缺失有 fallback;小程序能消费 Card Package。

## 15. 最终心智模型
```
旧: 照片 → 模板 → 参数 → 渲染 → "带特效的生日卡"
V2: 客户照片 + 重要时刻 → AI 看照片 → AI 理解构图 → AI 选择/设计方向
   → 3~4 个实际设计提案 → 制卡人员选择 → Procedural Renderer
   → Artwork → Material/Parallax/Holo → Card Identity → Card Package
   → Showcase / Collection
```
**最终目标**:客户打开卡片时第一反应是"**这是一件属于我的数字收藏品**",而不是"这是一个很酷的网页特效"。
