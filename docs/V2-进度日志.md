## 顺带修复(与文档方向无关,但影响日常出卡)✅ 2026-09-16
**问题**:`make_static_card` 偶发 `OSError: image file is truncated`(worker 日志中出现 2 次),静态卡出不来。
**根因**:图层写入**非原子** —— 读图方可能在 PNG 写到一半时读到半截文件。
**改动**:
- `card-studio/birthday_system.py`:新增 `_save_atomic()`,`source.png` 与**全部五层**改为「先写 `<name>.tmp.png` 再 `os.replace`」
- `card-studio/make_static_card.py`:新增 `load_layer()`(5 次退避重试 + 真正解码),`static.png` 改原子写
- `card-studio/render_previews.py`:新增 `safe_open()`
**测试**:逐项实测通过;**并发压力测试**(3 次重写图层 × 6 次出静态图并行)→ **0 错误**。
**已知问题**:无。

## 提前实施:Art Director(Phase 4 的核心,为 Phase 2 的「③提案」提供真实来源)✅ 2026-09-16
**为什么提前**:主规范 Phase 2 的完成标志是「**订单→分析→提案**→精修→QA→导出跑通」,而"提案"必须是
**实际卡面提案**(规范 §4 明确:不是模板缩略图)。没有提案引擎,Phase 2 的界面只能造假入口 → 先做引擎。

**新增文件**
| 文件 | 作用 |
|---|---|
| `card-studio/dl2/art_director.py` | 照片分析(程序度量 + 可选 AI 语义)+ **语言贴合度打分** + 产出 3~4 个真实提案 + `proposals.json` |
| `card-studio/server.mjs`(+2 接口) | `POST /api/analyze`(V2 步骤②)、`POST /api/proposals`(步骤③);新增 `/proposal/<卡>/<图>.png` 只读路由 |

**语言贴合度算法(确定性,可解释)**
| 语言 | 依据(PhotoDNA) |
|---|---|
| PORTRAIT | 主体占比 × 背景复杂度(edge_density) × 人脸可靠性 |
| CYBER | 暗调(明度)× 色彩浓度(saturation)× 细节密度 |
| MEMORY | 暖度 × 低饱和 × 低对比 |
| CINEMA | 光比(对比)× 偏暗 |
| EDITORIAL | 最大留白区评分 × 细节 × 曝光适中(不要求抠图) |

**实测(4 张验收照片, 结果随照片变化 ✓)**
| 照片 | 贴合度排序(前 3) | 理想语言 |
|---|---|---|
| 01-duo-closeup | portrait 0.63 > editorial 0.59 > memory 0.23 | portrait |
| 02-stairs-night | editorial 0.42 > cyber 0.25 > portrait 0.20 | editorial |
| 03-sea-hat | editorial 0.54 > portrait 0.42 > memory 0.22 | editorial |
| 04-sea-dress | editorial 0.58 > portrait 0.41 > memory 0.24 | editorial |

**端到端实测(项目 card-mu2o5m1y, 含 AI)**
- `POST /api/analyze` → 200,**10.8 秒**;贴合度 `editorial .419 / portrait .242 / cyber .227 / memory .205 / cinema .142`;
  **AI 语义**:「夜晚暖光下,女孩坐在古典石阶上望向镜头」,并建议 editorial ✓
- `POST /api/proposals {n:3}` → 200,**3.9 秒**;产出 A editorial / B memory / C cinema,三张图 HTTP 200 可访问 ✓
- `pending: ["portrait"]` —— 正确标注"该语言渲染器待 Phase 3"

**已知问题(重要,不要误判为完成)**
1. **渲染质量仍是 v1 级** —— 提案图是现有 DL2 渲染器直接产出,**尚未达到规范要求的"惊艳"标准**;
   且本次用空 `info` 渲染,文字层没有内容 → 看起来偏空。**这属于 Phase 3(四套语言各 1 标杆款)的工作**。
2. **PORTRAIT / CYBER 渲染器尚未实现** → 理想语言若是这两者,提案会退回已实现的三套(已在返回里用 `pending` 标注)。
3. 提案图较大(单张约 2.5MB,1024×1536 PNG);接入界面前建议加一档缩略图。

**下一步**:Phase 2 工作台 UI(用上面两个接口把「订单→分析→提案→精修→QA→导出」串起来),随后 Phase 3 补
PORTRAIT / CYBER 并统一提升四套语言的视觉质量。
